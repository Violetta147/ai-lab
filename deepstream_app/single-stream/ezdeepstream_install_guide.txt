Làm sao để khắc phục vấn đề kêt nối giữa wsl và máy A? tôi xin gọi máy host chứa wsl là máy B
Cách 1: Thiết Lập Port Forwarding Từ Windows Vào WSL2 (Dễ và An Toàn Nhất)
Giả sử kiến trúc của bạn:

Laptop A (RTSP Server/VLC): Đang phát RTSP ở cổng 8554 (ví dụ rtsp://<IP-A>:8554/mystream) và muốn xem kết quả ở cổng 8555.

DeepStream (WSL2 trên Laptop B): Kéo luồng từ <IP-A>:8554, xử lý, và đẩy luồng ra ở cổng 8555.

Tìm IP của WSL2
wsl hostname -I
Cấu hình Port Forwarding trên Windows
Mở PowerShell với quyền Administrator (Run as Administrator) trên Windows (Máy B) và chạy các lệnh sau (thay <IP-WSL2> bằng IP bạn vừa tìm được):
# Chuyển tiếp cổng RTSP đầu ra (8555) và UDP (5400) vào WSL2
netsh interface portproxy add v4tov4 listenport=8555 listenaddress=0.0.0.0 connectport=8555 connectaddress=<IP-WSL2>
netsh interface portproxy add v4tov4 listenport=5400 listenaddress=0.0.0.0 connectport=5400 connectaddress=<IP-WSL2>

Mở Tường Lửa Windows (Firewall)
New-NetFirewallRule -DisplayName "DeepStream RTSP" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8555,5400
New-NetFirewallRule -DisplayName "DeepStream UDP" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 8555,5400
Kết quả: Bây giờ, trên Laptop A, bạn mở VLC và kéo luồng bằng IP của Windows B: rtsp://<IP-Windows-B>:8555/ds-test. Windows sẽ tự động đẩy luồng này vào DeepStream trong WSL2.

Cách 2: Chuyển WSL2 Sang Chế Độ Mạng Mirrored (Mirrored Mode - Khuyến Nghị Cho Windows 11)
notepad $env:USERPROFILE\.wslconfig
[wsl2]
networkingMode=mirrored
# Các cấu hình khác của bạn (nếu có)
wsl --shutdown
Kết quả: Sau khi khởi động lại, WSL2 sẽ có cùng IP mạng LAN (ví dụ: 192.168.1.x) với Windows. Các luồng RTSP (cả in và out) sẽ không bị kẹt bởi lớp NAT nữa.
