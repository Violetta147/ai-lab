ffmpeg -re -stream_loop -1 -i "D:\datas\Final.yolov8\datasets\VID_20260404_160133.mp4" `
>> -rtsp_transport tcp `
>> -c:v libx264 -preset ultrafast -tune zerolatency `
>> -vf "scale=640:640" `
>> -b:v 2M -maxrate 2M -bufsize 1M `
>> -an `
>> -f rtsp rtsp://localhost:8554/mystream

-re: Đọc file theo thời gian thực (Native Frame Rate). Nếu không có cái này, FFmpeg sẽ đọc file cực nhanh (tốc độ tối đa của CPU), khiến luồng RTSP bị "vọt" và không xem được.
-stream_loop -1: Lặp lại file video vô tận
-i "D:\...\VID_20260404_160133.mp4": Đường dẫn đến file video
-rtsp_transport tcp: Ép buộc truyền dữ liệu qua giao thức TCP thay vì UDP
-c:v libx264: Sử dụng bộ mã hóa H.264 (phổ biến nhất, DeepStream hỗ trợ cực tốt)
-preset ultrafast Cấu hình mã hóa nhanh nhất có thể. Nó hy sinh dung lượng file để đổi lấy việc giảm tải cho CPU
-tune zerolatency: Tối ưu hóa đặc biệt để giảm độ trễ xuống mức thấp nhất. Nó loại bỏ việc đệm khung hình (B-frames), giúp hình ảnh truyền đi gần như ngay lập tức
-vf "scale=640:640": Resize video về đúng kích thước 640x640 để khớp hoàn toàn với input của model 
-b:v 2M -maxrate 2M -bufsize 1M: Giới hạn băng thông ở mức 2 Mbps
-an: Loại bỏ âm thanh (Audio None)
-f rtsp: Định dạng đầu ra là RTSP
rtsp://localhost:8554/mystream: Video File->FFmpeg->MediaMTX-> DeepStream
-keyint_min: (Thông thường đi kèm một con số, ví dụ -g 30) Dùng để ép buộc tạo khung hình chủ chốt (I-frame). Việc này giúp DeepStream "bắt" được luồng video nhanh hơn khi mới khởi động.
